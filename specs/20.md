# Spec 20 — RAG evaluation

Source: `EXECUTION_PLAN.md` Phase 20 and `CLAUDE.md` (Logging and evaluation). Dataset: `evaluation/evaluation_dataset.jsonl` (Phase 19, 49 questions).
Status: confirmed by the developer on 2026-10-07, with all five proposals as written (judge: anthropic/claude-haiku-4.5).

## Goal

A repeatable evaluation that runs every dataset question through the real system and measures retrieval, answer
correctness, groundedness, relevance and unsupported claims, plus latency and cost, and saves the results as JSON for
one strategy at a time. Phase 21 then runs it for vector-only and hybrid and compares them.

## Acceptance criteria

| ID | Criterion | Source |
|---|---|---|
| AC-001 | An evaluation runner sends every question in the dataset through the real pipeline (`rag.answer_question`) with a chosen retrieval strategy, and records the answer, the chunks sent to the model, the tool calls, tokens, cost and latency. | 20; CLAUDE.md "custom evaluation first" |
| AC-002 | Retrieval is measured per question and in total: whether a correct source appeared among the chunks sent to the model, **Recall@5** and **Recall@8** (share of the expected films found in the top 5 / 8 chunks) and **Precision@5** (share of the top 5 chunks that belong to an expected film). For recommendations the expected films are the acceptable ones. No-answer questions are left out of retrieval metrics. | 20 Retrieval "did correct source appear? Recall@K, Precision@K" |
| AC-003 | **Answer correctness** is judged against the expected answer (and the acceptable films for recommendations; for no-answer questions, correct means it says the film is not in the data and does not answer from memory): correct = 1, partially correct = 0.5, incorrect = 0. `answer_accuracy` is the average. | 20 Answer "correctness" |
| AC-004 | **Groundedness and unsupported claims:** the judge lists the answer's factual claims and marks each as supported or not by the sources and tool results the model was given. Groundedness = supported / all claims, averaged over answers; the hallucination rate = share of answers with at least one unsupported claim; unsupported claims are listed in the results. | 20 "groundedness", Hallucination "did answer contain unsupported claims?" |
| AC-005 | **Relevance:** the judge rates whether the answer addresses the question (yes = 1, partly = 0.5, no = 0), averaged. | 20 Answer "relevance" |
| AC-006 | Results are saved as JSON per strategy with at least `strategy`, `retrieval_recall_at_5`, `answer_accuracy`, `groundedness`, `avg_latency_ms`, `avg_cost_usd`, plus the other metrics, a breakdown by question type, and every question's details. | CLAUDE.md "Save results as JSON per strategy with …" |
| AC-007 | The judge returns structured output that is validated; a failed or invalid judgement marks that question "not judged" and is reported, instead of crashing the run or counting as a score. The judge's own cost is reported separately from the system's cost. | reliability; CLAUDE.md "never write a metric that was not measured" |

## Design decisions the plan does not state (confirmed)

1. **Judge model: an LLM-as-a-judge from a different vendor than the system's models.** The answers come from Xiaomi
   (MiMo) and the translation from Google (Gemini); a model grading its own answers tends to favour them. Options, with
   my cost estimates per full run of 49 questions:
   - **`anthropic/claude-haiku-4.5`** (recommended): careful, reliable structured output, about **$0.25** per run.
   - `openai/gpt-5-mini`: cheaper (about $0.08), a reasoning model, so slower.
   - MiMo grading itself: about $0.03, but self-grading bias.
2. **One judge call per question** that returns correctness, relevance and the claim list together, so the judge reads
   the sources once. The judge gets: the question, the expected answer (and acceptable films), the system's answer, and
   exactly the sources and tool results the system's model saw.
3. **Rule checks next to the judge:** `must_contain_any`, "expected film retrieved" and "expected tool used" are computed
   without an LLM and reported beside the judge's scores. Where the rule check and the judge disagree, the question is
   flagged for a human look. That also gives a measure of how far the judge can be trusted.
4. **RAGAS later, if at all.** The plan says custom evaluation first and RAGAS optional; RAGAS would add a heavy
   dependency, so it is left out unless the custom results raise a question it would answer.
5. **This phase runs the default (hybrid) strategy once.** Phase 21 runs vector-only too and compares. One run costs
   about $0.04 for the system's answers plus the judge, and takes roughly 15–25 minutes because answers take 15–30 s each.
