# Spec 18 — Hybrid search

Source: `EXECUTION_PLAN.md` Phase 18 (18.1–18.3) and `CLAUDE.md` (Retrieval and generation, API contract).
Status: confirmed by the developer on 2026-10-07, with all five proposals as written.

## Goal

Retrieval uses both searches built so far: vector search (meaning) and keyword search (exact words). Their results
are fused into one ranked list, and the best chunks of that list go to the model. Vector-only stays available, and
the two strategies are compared on the same questions.

## Acceptance criteria

| ID | Criterion | Source |
|---|---|---|
| AC-001 | For each question, vector search (top N) and keyword search (top N) both run, on the translated query and its keywords. | 18.1 "run both searches, e.g. vector top 10, keyword top 10" |
| AC-002 | The two result lists are fused into one ranking with Reciprocal Rank Fusion: each chunk scores Σ 1 / (k + rank) over the lists it appears in; ties are broken deterministically. | 18.2 "fuse/rerank … Reciprocal Rank Fusion"; CLAUDE.md "fuses the results with Reciprocal Rank Fusion or weighted scoring" |
| AC-003 | The top `RETRIEVAL_TOP_K` (8) fused chunks are what the model receives and what `sources` lists. `debug.selected_chunks` holds them, and each selected chunk records which search(es) found it, its rank in each, and its fused score. `vector_results` and `keyword_results` stay as they are. | 18.2 "create final result set"; Phase 12 debug object |
| AC-004 | The strategy is configuration: `RETRIEVAL_STRATEGY` = `hybrid` or `vector`, so the strategies can be compared. | 18.3 "run vector-only vs hybrid"; Phase 21 |
| AC-005 | When keyword search has nothing to add (no keywords, no matches), hybrid returns the vector results unchanged. | no regression of Phase 6 behaviour |
| AC-006 | A comparison run on a fixed question set reports, for vector-only and hybrid: whether the expected film is ranked first (hit@1), whether it is among the chunks sent to the model (hit@8), and, for questions about two films, whether both are among them. | 18.3 "compare performance" |

## Design decisions the plan does not state (confirmed)

1. **Fusion: Reciprocal Rank Fusion, not weighted scores.** RRF only uses each chunk's *position* in each list. A cosine
   distance (vector) and a ts_rank (keyword) are on different, unrelated scales, so weighted scoring would first need both
   normalised and the weights tuned. RRF needs neither and is the standard choice.
2. **Sizes: top 10 from each search, top 8 of the fused list to the model.** The plan's example is "top 10 each"; 8 is
   the current `RETRIEVAL_TOP_K`, so prompt size and cost stay the same.
3. **RRF constant k = 60**, the value from the original RRF paper. A larger k flattens the difference between rank 1 and
   rank 10; 60 is the common default.
4. **Keyword noise: measure first.** Phase 17 showed generic keywords ("crime", "thriller", "best films") match hundreds of
   chunks. Start with plain RRF, where a chunk found by only one list at rank 1 scores less than one found high in both.
   If the comparison shows noise hurting, add one fix: leave genre names and generic words out of keyword search. The
   README would record which was needed.
5. **Default after this phase: hybrid**, unless the comparison shows it doing worse than vector-only. If it does, keep
   vector as the default and say so.

AC-006 comparison (54 questions; same translation and same searches for both strategies):

| Questions | Strategy | hit@1 | hit@8 | both films @8 | films among the 8 |
|---|---|---|---|---|---|
| all 54 | vector | 0.98 | 1.00 | 0.91 | 2.04 |
| all 54 | hybrid | 0.94 | 1.00 | 0.96 | 3.59 |
| 8 two-film | vector | 1.00 | 1.00 | 0.38 | 1.62 |
| 8 two-film | hybrid | 1.00 | 1.00 | 0.75 | 3.12 |

Proposal 4 (keyword noise) was measured on identical translations (`docs/experiments/hybrid_variants.json`): leaving
genre names and generic words out of keyword search lowered two-film both@8 from 0.75 to 0.50, so it was not adopted.
Breaking score ties in favour of the vector rank was better than or equal to a chunk-id tie-break on every metric
(hit@1 0.93 → 0.94, casual hit@1 0.94 → 1.00, fewer off-target films), so it was adopted.

Proposal 5: hybrid is the default. It keeps hit@8 at 1.00 and doubles two-film coverage; it ranks a different film
first on 2 of the 30 known-answer questions (kidnapping-themed keywords lift Man on Fire and Taken above Prisoners).

Browser check: "Compare Prisoners with Zodiac" now sends 6 Zodiac chunks, 1 Prisoners chunk (keyword #2) and 1 The
Batman chunk (keyword noise) to the model, where vector-only sent 8 Zodiac chunks.
