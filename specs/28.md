# Spec 28 — Testing

Source: `EXECUTION_PLAN.md` Phase 28 ("Test separately": backend, RAG, tools, security, MCP) and `CLAUDE.md`.
Status: confirmed by the developer on 2026-10-08, with all six proposals as written.

## Goal

Each of the plan's five groups can be tested on its own, every item the plan lists under a group has tests, and a
traceability table shows which tests cover which item. Most items were tested in earlier phases (240 tests in 22
files); this phase fills the gaps and makes the coverage visible.

## Design decisions the plan does not state (proposals)

1. **Groups as pytest markers, assigned per test file in `conftest.py`** (e.g. `test_mcp.py` → `mcp`), so existing
   files are not moved. Alternative: move files into `tests/backend/`, `tests/rag/` … folders: clearer on disk, but it
   rewrites history and imports for 22 files.
2. **RAG retrieval tests use recorded query embeddings.** A script embeds the test questions once (about 15 questions,
   under $0.0001) and saves the vectors in `backend/tests/fixtures/query_embeddings.json`. The tests then run against the
   real database for free and give the same result every time (they skip when the database is down, like the others).
   If the embedding model changes, the script is run again. Alternative: call the embedding API in every test run
   (not free, not deterministic, and blocked by the paid-API guard).
3. **Live tests are opt-in** (`pytest -m live`, excluded by default). The paid-API guard is lifted only for them. One run
   of the live RAG questions costs about $0.01 (estimate: 5 questions × MiMo + Gemini); the injection attacks about
   $0.01 more.
4. **New test questions**, not copied from the 49 evaluation questions or the 54 tuning questions, so the tests do not
   reward tuning to a known set. Planned (all checked to exist, or not exist, in the data):
   - known: "What do critics think of Whiplash?", "How was the acting in Get Out received?"
   - vague: "the film where a desperate father kidnaps the man he suspects took his daughter" (*Prisoners*; the first
     wording, "a father hunts for his kidnapped daughter", also fits *Taken*, which the model chose in a live run), "the movie about a ballerina
     losing her grip on reality" (*Black Swan*), "the animated one where an old man flies his house with balloons"
     (*Up*), "the thriller about a man who cannot form new memories" (*Memento*), "something scary" (horror majority)
   - no-answer: "What do critics say about Parasite?", "Is Oppenheimer worth watching?"
5. **Malicious arguments are run against the MCP server in-process** (the same protocol messages as over stdio, as in
   `test_mcp`), plus one stdio check, so the matrix stays fast.
6. **The frontend is out of scope here:** the plan's list names no frontend tests. It is checked by `npm run build`
   (types, lint) and in the browser, as so far.

## Findings while building it

- **Bug fixed: a NUL byte in a title crashed three tools.** `"Zodiac\x00"` passed validation and reached PostgreSQL,
  which rejects NUL in text, so `compare_movies`, `rating_summary` and `get_movie_metadata` answered `TOOL_FAILED`.
  Titles with control characters are now `INVALID_ARGUMENTS` (`app/tools.py`, `_clean_title`).
- **A vague question can be vague in more than one way.** "The film where a father hunts for his kidnapped daughter"
  retrieved *Prisoners*, but in the live run the model answered *Taken* (2008), which fits too and is in the data.
  The test, not the system, was wrong; the question now names something only *Prisoners* has.
- **The translator often resolves vague questions from its own knowledge.** For "a ballerina losing her grip on
  reality" Gemini already adds the keyword "Black Swan", for the balloon house "Up", for Oppenheimer "Christopher
  Nolan". Vague questions work partly because the translation model recognises the film, not only because of
  semantic search.
- **`pytest -m rag` first ran the live tests too** (a `-m` on the command line replaces the default `-m "not live"`),
  spending about $0.02 unannounced. Live tests are now left out unless the expression names `live`, and a test checks it.
- **3 of the 5 poisoned-review attacks no longer reach the model.** In Phase 16 (vector search) all 5 poisoned reviews
  were retrieved; with hybrid search (Phase 18) only 2 are, so those 3 attacks are skipped, not passed. The 5 that ran
  (2 poisoned reviews, 3 user attacks) were all defended. Open: rewrite the 3 attack questions so their poison is
  retrieved again, as R5 was in Phase 16.
